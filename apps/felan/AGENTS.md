# Felan clients

- `@felan-ai/felan` owns the `felan` CLI, TUI, ACP and headless clients, local service providers and packaged default `host.json`. It depends on the exact installed `@felan-ai/daemon` version and resolves the daemon entrypoint through package resolution, never cwd-relative paths.
- The daemon owns admission, canonical sessions, process lifetime and persistence. Local providers run within that ownership boundary and supply local settings, credentials and runtime composition. TUI, ACP and headless remain clients; do not move execution or canonical store ownership into a client renderer.
- Preserve the fixed resource boundary: source-controlled built-ins, Felan-owned settings/appends, explicit global/workspace agent definitions and Agent Skills, the Agent Core-selected cwd `AGENTS.md`/`CLAUDE.md`, and host-configured Pi extensions. The TUI accepts explicit local paths through `--extension`/`-e`; optional `piExtensions` user/project directories apply to every new root after Felan folder trust, and children inherit their root's paths. Only the creating TUI with selection support may prompt for undecided project trust; other creators skip those directories without saving a decision. Ambient Pi packages, prompts, themes, skills, project settings and network/package sources remain filtered.
- Every new, resumed, forked, cloned or imported root session gets a host-path runtime whose cwd resolves relative paths and scoped services keyed by its stable session identity. Nested sessions share the root storage mapping. Settle execution services before Pi disposal and retain UI through asynchronous shutdown handlers.
- Runtime dependency installation is an explicit provider-owned operation: apply host policy, then obtain an eligible local-console answer when required. Client kind and ordinary session forms grant no authority. Preserve graceful unavailability in headless, remote and cloud contexts; never install during extension startup or an ordinary model tool call.
- Run client and daemon tests only through `scripts/test-isolated.sh`, which supplies a fresh HOME, agent directory and TMPDIR. From this directory use `../../scripts/test-isolated.sh pnpm test`.
