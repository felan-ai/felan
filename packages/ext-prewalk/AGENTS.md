# Prewalk Extension

- Preserve the same-session state machine: `/prewalk` can arm an idle session and `enter_prewalk` can enter planning from an active model turn. A tool-entered run must observe planning guidance in a later model turn before the first successful code mutation can trigger handoff. Never fork or replace useful history.
- Keep current phase guidance transient and inject it exactly once at a stable context position within that phase. Successful entry-tool controls and stale or other-phase guidance stay out of model context. Preserve compact append-only bounded continuations, session-scoped tier and exact-model target resolution, planner model and thinking restoration on settle/shutdown, deferred restoration for exit requests during active inference, and cancellation on manual model changes. An in-flight internal model switch must never overwrite a later manual selection.
- Keep the Tasks workflow in phase guidance. When both `TaskCreate` and `TaskUpdate` are active, the handoff gate may inspect successful `TaskCreate` and `TaskUpdate` calls that claim work with `status: in_progress`; do not inspect `TaskList`, `TaskGet`, todo, or Beads activity at runtime. If the task tools are unavailable, preserve mutation-only handoff behavior. Qualify only explicit mutation tools (`edit`, `write`, and Codex `apply_patch`), not general shell tools; keep tool-result qualification in `state.ts` and lifecycle/model orchestration in `index.ts`.
